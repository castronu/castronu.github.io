Quatre pièces. Le pilote en contient une, le projet toutes.

Ce que je construis

N°PièceCe qu'elle fait
1Agents d'exploitation

Ils enquêtent sur un incident en lisant le cluster, les logs, les métriques et le code, en lecture seule. Quand un changement est nécessaire, ils rédigent un plan : une personne l'approuve dans une application sans IA et un service séparé l'exécute.

2Relecteur de pull requests

Commente chaque pull request.

3Agents qui écrivent du code

Un poste de travail dans le cloud où Claude Code, Codex et des outils similaires travaillent seuls et rendent une branche, une pull request et un environnement de prévisualisation vérifié.

4Mémoire partagée

Un dépôt Git de skills, de runbooks et de décisions, lu par les agents et par les outils des développeurs. Chaque ajout passe par une relecture, comme le code.

Chaque livraison inclut les evals : des tests automatiques du comportement des agents, relancés à chaque changement de modèle ou de prompt. Les agents se connectent à Slack ou Microsoft Teams, GitHub ou GitLab, et aux modèles que vous utilisez déjà.

Je l'ai déjà construite une fois

Je l'ai conçue et construite, presque seul, pour une plateforme SaaS de streaming en direct, où une petite équipe de développement l'utilise chaque jour : cinq agents spécialisés, 19 serveurs d'outils en lecture seule.

Je ne réutilise pas ce code pour vous : je repars de zéro avec la même conception, sur votre cloud et vos outils.

Questions fréquentes

Mes données sortent-elles de mon cloud ?

Les agents tournent dans votre compte. Les données ne vont qu'au fournisseur de modèles que vous avez choisi.

Puis-je donner aux agents des droits d'écriture ?

Oui. On part de la lecture seule, avec chaque changement approuvé ; à partir de là, c'est vous qui décidez.

Faut-il Kubernetes ?

Oui, sur AWS, Google Cloud ou Azure.

Que me reste-t-il à la fin ?

Tout : le code, la configuration, la mémoire et les tests, dans vos dépôts.
